# Mobile combat and rendering polish

Arcade has a circular movement pad: left/right move, up jumps once per upward gesture, down crouches. Releasing, cancelling, losing pointer capture, blurring or hiding clears input. The pad is intentionally side-on; it does not turn Arcade into a free-roaming 3D game.

Three combat buttons replace four: Strike changes to Backhand after a confirmed light, Breaker after backhand/sweep, and Storm ender after heavy if available. Hold Guard and tap Strike to request a heavy counter; stun and block-stun still prevent illegal attacks. Storm remains directly available. Keyboard J/J/K/U can follow the same chain. Sweep (crouching J) and aerial (airborne J) are selected by the server. No client-specified variant can bypass the move rules. Whiffs cannot cancel. Existing damage scaling and cooldown apply.

Solo retains its movement constants, prediction, combat rules, collision and saves. Camera arrows beside the movement stick reuse the existing 45-degree orbit controls. Strike follows the existing light/backhand/heavy route and uses the charged finisher. Guard, Roll and Storm stay directly available; Heal appears only when needed, and the existing nearby-interaction button replaces the redundant Use button.

Arcade High uses the existing cinematic pass (subtle bloom and colour grading), soft 2048 shadows on desktop / 1024 on coarse-pointer devices. Performance bypasses the pass and shadows. Existing licensed models are unchanged; this is not a photorealistic asset upgrade. Material flash updates are cached rather than traversing each model every frame, and offscreen lobby character previews stop rendering.

Verification: 81 unit/integration tests passed; build passed. Browser inspection confirmed both characters render, no console errors, Solo camera arrows work and the compact controls fit 844x390 landscape bounds. High preview reported 43 draw calls / 423532 triangles; these are scene counters, not a device FPS guarantee. No physical touchscreen or real internet multiplayer latency test was available. The isolated Solo playthrough reached the boss but died before extraction; its win assertion failed. Solo simulation files were unchanged.

Reaction follow-up: Arcade now selects the existing Ember Knight hit_chest clip on authoritative stun, braces guard with local joint offsets, and applies bounded recoil for rigs without a hit clip. Attack sampling uses wind-up/contact/recovery phases and up to 50 ms of presentation interpolation between snapshots. No movement, damage, timing or collision rules changed. Overlay restoration is regression-tested to prevent cumulative bone drift. 82 tests and build pass. Browser match renders without console errors; the current Wraith asset lacks authored hit/guard clips, so this remains a limited procedural fallback rather than realistic motion capture. Physical-device and detailed animation-contact review remain necessary.

Movement/audio follow-up: Arcade attacks retain server-authoritative horizontal steering (jab 80%, light 65%, kick 40%, heavy 35%, special 25% of normal speed). Stun, blocking, stale-input stopping and arena bounds still apply. This remains side-on Arcade, not free-roaming 3D. Existing CC0 punch recording now handles bodily hits; weapon contacts use chop and blocks use metal. Removed stacked pitched impact tones and repeated combo speech. 86 tests and build pass; physical multitouch and subjective audio listening still need user review. Solo movement is unchanged.

Arena effects follow-up: pooled blood droplets on authoritative hits only, never blocks; persistent Blood toggle; fewer droplets in Performance/reduced-motion. Existing licensed HDR now supplies the sky, and High mode animates a subdivided water surface. No new model assets or photorealism claim. Impact recordings use bounded low-pass filtering and short fade-outs, with quiet weapon transients. 86 tests and build pass. Browser rendered the arena and toggle with no console errors. Audio realism and mobile frame rate need listening/device review.
